# คู่มือติดตั้งลง Google Apps Script

เอกสารนี้สำหรับคนที่จะติดตั้งระบบครั้งแรก เปิดวางข้างๆ หน้า Apps Script แล้วทำตามได้จนจบ

ใช้เวลาประมาณ **20 นาที** ถ้าใช้ clasp · **40–50 นาที** ถ้า copy-paste เอง

---

## 1. ต้องทำใน Google Sheet หรือทำเป็น script แยก?

### **ตอบ: script แยก (standalone) — ไม่ผูกกับชีต**

| วิธีสร้างโปรเจกต์ | ได้อะไร | ใช้ไหม |
|---|---|---|
| เปิด Google Sheet → `Extensions` → `Apps Script` | script ผูกติดกับชีตนั้น (container-bound) | ❌ **ห้ามใช้** |
| ไปที่ **script.google.com** → `New project` | script แยกอิสระ (standalone) | ✅ **ใช้อันนี้** |

### ชีตที่เก็บข้อมูล ไม่ใช่ชีตที่ผูกสคริปต์ — คนละไฟล์กัน

นี่คือจุดที่เข้าใจผิดกันบ่อยที่สุด

```
  ┌─────────────────────────────────┐
  │  Apps Script project            │   ← โค้ดอยู่ที่นี่ (standalone)
  │  (script.google.com)            │
  └─────────────────────────────────┘
                 │
                 │  รัน setup() ครั้งเดียว — ระบบสร้างให้เอง
                 ▼
  ┌─────────────────────────────────┐
  │  Buyer Procurement Activity—DB  │   ← ข้อมูลอยู่ที่นี่ (Google Sheets)
  │  9 ชีต                          │
  └─────────────────────────────────┘
```

สคริปต์จำ Spreadsheet ID ไว้ใน Script Properties ไม่ได้ผูกกับชีตใดชีตหนึ่งตายตัว
ถ้าวันหนึ่งต้องย้าย DB ก็แก้ค่านั้นค่าเดียว

---

## 2. เตรียมเครื่อง

ต้องมี [Node.js](https://nodejs.org/) และ [clasp](https://github.com/google/clasp)

```bash
npm i -g @google/clasp
clasp login          # เข้าสู่ระบบด้วยบัญชีที่จะเป็น "เจ้าของระบบ"
```

บัญชีที่ใช้ `clasp login` จะกลายเป็นเจ้าของโปรเจกต์และเป็นบัญชีที่รันโค้ดแทนผู้ใช้ทุกคน
**ควรเป็นบัญชีขององค์กร ไม่ใช่บัญชีส่วนตัว**

---

## 3. สร้างโปรเจกต์และอัปโหลดโค้ด

1. ไปที่ [script.google.com](https://script.google.com) → `New project`
2. ตั้งชื่อโปรเจกต์ เช่น `ระบบติดตามกิจกรรมจัดซื้อ`
3. `Project Settings` (รูปเฟือง) → คัดลอก **Script ID**
4. เปิด `.clasp.json` ใน repo แก้เฉพาะบรรทัด `scriptId`

```json
{
  "scriptId": "วางรหัสที่คัดลอกมาตรงนี้",
  "rootDir": "src",
  "fileExtension": "js"
}
```

> **อย่าใช้ `clasp create`** เพราะจะเขียนทับ `.clasp.json` ทั้งไฟล์ และ `rootDir` จะหายไป
> **อย่าแก้ `rootDir`** — ดูหัวข้อ 7 ว่าทำไม

5. อัปโหลด

```bash
clasp push     # 33 ไฟล์: server 23 + client 10
clasp open     # เปิดโปรเจกต์ในเบราว์เซอร์
```

**ตรวจว่า push ถูก:** ใน Apps Script editor ต้องเห็นชื่อไฟล์ขึ้นต้นด้วย `server/` และ `client/`
ถ้าเห็น `src/server/` แปลว่า `rootDir` หายไป กลับไปแก้ `.clasp.json` แล้ว push ใหม่

## 4. รัน `setup()`

ในหน้า Apps Script editor

1. เลือกไฟล์ `server/Setup` จากแถบซ้าย
2. เลือกฟังก์ชัน `setup` จาก dropdown ด้านบน
3. กด **Run**
4. หน้าต่างขออนุญาตสิทธิ์จะเด้งขึ้น → `Review permissions` → เลือกบัญชี →
   `Advanced` → `Go to <ชื่อโปรเจกต์> (unsafe)` → `Allow`

   (คำว่า unsafe เป็นข้อความมาตรฐานของ Google สำหรับสคริปต์ที่ยังไม่ผ่านการตรวจ ไม่ได้แปลว่ามีปัญหา)

5. เปิด **Execution log** จะเห็น URL ของไฟล์ DB ที่ระบบสร้างให้ — เก็บลิงก์นี้ไว้

`setup()` รันซ้ำได้เสมอโดยปลอดภัย: สร้างเฉพาะชีตที่ยังไม่มี เพิ่มคอลัมน์ใหม่ต่อท้ายชีตเดิม
โดยไม่ย้ายหรือลบคอลัมน์ใด และใส่ข้อมูล Config เฉพาะแถวที่ยังไม่มี

## 5. ตั้งค่าในไฟล์ DB

เปิดไฟล์ Google Sheets ที่ `setup()` สร้างให้

### 5.1 ใส่รายชื่อบริษัทในเครือ — **ข้อนี้สำคัญที่สุด**

ไปที่ชีต **`Config_Lists`** แล้วเพิ่มแถวสำหรับทุกบริษัทที่อาจเป็นผู้จัดซื้อ

| List_Name | Code | Label_TH | Parent_Code | Sort_Order | Is_Active |
|---|---|---|---|---|---|
| `COMPANY` | `PLANB` | บริษัท แพลน บี มีเดีย จำกัด (มหาชน) | | 10 | TRUE |
| `COMPANY` | (รหัสย่อบริษัทในเครือ) | (ชื่อเต็มตามหนังสือรับรอง) | | 20 | TRUE |
| `COMPANY` | … | … | | 30 | TRUE |

ระบบใส่ `PLANB` ให้แถวเดียวเป็นตัวอย่าง ถ้ายังไม่เพิ่มบริษัทในเครือ `verifyDeployment()`
จะขึ้นคำเตือนข้อ "ข้อมูลตัวอย่างที่ต้องแทนที่" และ Buyer จะเลือกบริษัทตอนปิดงานได้แค่รายการเดียว

`Code` คือสิ่งที่ถูกเก็บลงฐานข้อมูล ตั้งให้สั้น เป็นภาษาอังกฤษ และ**ห้ามเปลี่ยนทีหลัง**
(งานเก่าที่ปิดไปแล้วอ้างถึงรหัสนี้) ส่วน `Label_TH` แก้ได้ตลอด

### 5.2 แก้หน่วยงานให้ตรงกับบริษัท

`DEPARTMENT` ที่ระบบใส่ให้ (`OPS` / `MKT` / `FIN`) เป็นตัวอย่าง แก้ให้ตรงกับผังองค์กรจริง

### 5.3 ตรวจค่าตั้งค่า

ชีต **`Config_Settings`** — ดูตารางในหัวข้อ 5 ของ `README.md`
ค่าเริ่มต้นใช้ได้ทันที ยกเว้นถ้าต้องการเปลี่ยนเวลาส่งอีเมลเตือน

### 5.4 เพิ่มผู้ใช้

ชีต **`Users`** — บัญชีที่รัน `setup()` ถูกเพิ่มเป็น `ADMIN` ให้แล้ว เพิ่มคนที่เหลือ

| Email | Name | Role | Responsible_Scope | Is_Active |
|---|---|---|---|---|
| `buyer.a@company.co.th` | สมชาย ใจดี | `BUYER` | | `TRUE` |
| `head@company.co.th` | หัวหน้าฝ่ายจัดซื้อ | `HEAD` | | `TRUE` |

อีเมลต้องตรงกับบัญชี Google ที่ผู้ใช้จะใช้เข้าระบบ **ต้องมีอย่างน้อยหนึ่ง `ADMIN` และหนึ่ง `HEAD`**

## 6. ตั้ง trigger และ deploy

### 6.1 อีเมลแจ้งเตือนรายวัน

กลับไปหน้า Apps Script → เลือกฟังก์ชัน `installTriggers` → **Run** หนึ่งครั้ง
(รันซ้ำได้ ระบบจะลบ trigger เก่าให้ก่อนเสมอ จึงไม่มีทางได้อีเมลซ้ำ)

### 6.2 Deploy เป็น Web app

`Deploy` → `New deployment` → กดรูปเฟืองเลือก type `Web app`

| ตัวเลือก | ค่าที่ต้องใช้ | เหตุผล |
|---|---|---|
| Execute as | **Me (บัญชีเจ้าของระบบ)** | ผู้ใช้เข้าถึงข้อมูลผ่านโค้ดเท่านั้น ไม่ต้องแชร์ไฟล์ DB ให้ใคร |
| Who has access | **Anyone within (โดเมนบริษัท)** | จำกัดเฉพาะคนในองค์กร |

กด `Deploy` แล้วคัดลอก **Web app URL** ไปแจกให้ผู้ใช้

> ⚠️ **ห้ามตั้ง `Who has access` เป็น `Anyone`** เพราะใครก็ตามที่ได้ลิงก์จะเปิดหน้าเว็บได้
> (ระบบจะยังปฏิเสธคนที่ไม่มีในชีต `Users` แต่ไม่ควรเปิดให้ถึงขั้นนั้น)

เลือกฟังก์ชัน `verifyDeployment` → **Run** → เปิด Execution log

```

[ ผ่าน ]   1. ไฟล์ฐานข้อมูล
[ ผ่าน ]   2. ชีตและหัวคอลัมน์ครบตาม Schema
[ ผ่าน ]   3. รหัสประจำตัว (primary key) ไม่ซ้ำ
[ ผ่าน ]   4. ไฟล์หน้าเว็บ (ตรวจชื่อที่ clasp ตั้งให้จริง)
[ ผ่าน ]   5. ค่าตั้งค่าหลัก
[ เตือน ]  6. โฟลเดอร์หลักใน Google Drive
[ ผ่าน ]   7. รายการ dropdown ที่จำเป็น
[ เตือน ]  8. ข้อมูลตัวอย่างที่ต้องแทนที่ด้วยของบริษัท
             ยังเป็นค่าตัวอย่างที่ระบบใส่ให้: DEPARTMENT (OPS, MKT, FIN) · COMPANY (PLANB)
[ ผ่าน ]   9. สถานะงานและเส้นทางที่ไปต่อได้
[ ผ่าน ]  10. ผู้ใช้งาน
[ ผ่าน ]  11. อีเมลแจ้งเตือนรายวัน
[ ผ่าน ]  12. การ Deploy เป็น Web app
[ ผ่าน ]  13. โควตาอีเมลคงเหลือวันนี้

สรุป: ผ่าน 11 · เตือน 2 · ไม่ผ่าน 0
================================
```

| ระดับ | ความหมาย |
|---|---|
| **ไม่ผ่าน** | ระบบใช้งานไม่ได้ ต้องแก้ก่อน |
| **เตือน** | ใช้งานได้ แต่ยังไม่ควรเปิดให้ทั้งฝ่ายใช้ |
| **ผ่าน** | เรียบร้อย |

**ข้อ 4 และข้อ 8 คือข้อที่ควรดูให้ดีที่สุด**

- **ข้อ 4** เป็นสิ่งเดียวที่ชุดทดสอบบน Node พิสูจน์แทนไม่ได้ — มันตรวจว่า clasp ตั้งชื่อไฟล์ HTML
  ทั้ง 10 ไฟล์ตรงกับที่โค้ดเรียกหาจริงหรือไม่ **ก่อน**ที่จะมีผู้ใช้คนไหนเปิดหน้าเว็บแล้วเจอจอว่าง
- **ข้อ 8** กันไม่ให้เปิดใช้งานจริงทั้งที่ `COMPANY` ยังมีแต่บริษัทแม่ และ `DEPARTMENT`
  ยังเป็นค่าตัวอย่าง

## 8. ติดตั้งโดยไม่ใช้ clasp (copy-paste เอง)

ถ้าลง Node ไม่ได้ ทำตามนี้แทนขั้นตอนที่ 3

ใน Apps Script editor กด `+` ข้างคำว่า `Files` แล้วสร้างทีละไฟล์
**ชื่อไฟล์ต้องตรงตามตารางนี้เป๊ะ** (Apps Script เติมนามสกุลให้เอง — อย่าพิมพ์ `.gs` หรือ `.html`)

### ไฟล์ `Script` (23 ไฟล์) — เลือก `Script` ตอนสร้าง

```
server/ActivityService   server/Api              server/Auth
server/Bootstrap         server/CaseService      server/CaseWorkflow
server/ChangeLog         server/Config           server/DriveService
server/Errors            server/IdGenerator      server/Main
server/Notification      server/Repository       server/Rules
server/Schema            server/Setup            server/StatusEngine
server/TeamService       server/Utils            server/Validation
server/VendorService     server/Verify
```

แต่ละไฟล์ให้คัดลอกเนื้อหาจาก `src/server/<ชื่อเดียวกัน>.js`

### ไฟล์ `HTML` (10 ไฟล์) — เลือก `HTML` ตอนสร้าง

```
client/Index             client/Styles           client/App.js
client/views/MyCases     client/views/CaseDetail client/views/CaseStatus
client/views/CaseActivity client/views/CaseHistory
client/views/Vendors     client/views/TeamView
```

- `client/App.js` มาจากไฟล์ `src/client/App.js.html` (ตัดเฉพาะ `.html` ท้ายสุดออก)
- ไฟล์ที่เหลือมาจาก `src/client/<ชื่อ>.html` และ `src/client/views/<ชื่อ>.html`

### ตั้งค่า manifest

กด `Project Settings` → ติ๊ก `Show "appsscript.json" manifest file in editor`
แล้วกลับมาที่ `Files` จะเห็น `appsscript.json` — แทนที่เนื้อหาทั้งหมดด้วย `src/appsscript.json`

จากนั้นทำต่อจากขั้นตอนที่ 4 ได้เลย

## 9. แก้รายการ dropdown เอง (ไม่ต้องแก้โค้ด)

ทุก dropdown ในระบบ — ประเภทกิจกรรม บริษัทที่จัดซื้อ หน่วยงาน ช่องทางติดต่อ ประเภทงบ —
อ่านจากชีต **`Config_Lists`** ชีตเดียว ผู้ดูแลระบบเพิ่ม แก้ชื่อ หรือปิดการใช้งานได้เองตลอด
โดยไม่ต้องแตะโค้ดและไม่ต้อง deploy ใหม่

### ตัวอย่าง: เพิ่มประเภทกิจกรรม

เปิดไฟล์ DB → ชีต `Config_Lists` → เพิ่มแถวต่อท้าย

| List_Name | Code | Label_TH | Parent_Code | Sort_Order | Is_Active |
|---|---|---|---|---|---|
| `ACTIVITY_TYPE` | `SITE_MEETING` | ประชุมหน้างานกับผู้รับเหมา | `M1` | 45 | TRUE |

- **`Parent_Code` ของ `ACTIVITY_TYPE` ต้องเป็น `M1`** ไม่งั้นจะไม่ขึ้นในฟอร์มบันทึกกิจกรรม
  (ลิสต์อื่นเว้นว่างไว้ ยกเว้น `SUB_TYPE` ที่ใช้เป็นรหัสประเภทงบ)
- `Sort_Order` คุมลำดับใน dropdown — ใส่เลขคั่นกลางได้ ไม่ต้องเรียงใหม่ทั้งชุด
- `Is_Active` ต้องเป็น `TRUE`

จากนั้น **ล้าง cache** ให้ค่าใหม่มีผลทันที: ให้ผู้ใช้บทบาท `ADMIN` เรียก `api_clearCache`
(หรือรอไม่เกิน 10 นาที ระบบจะอ่านชีตใหม่เอง)

### ข้อควรระวัง 3 ข้อ

| แก้อะไร | ผลที่ตามมา |
|---|---|
| **`Label_TH`** | ปลอดภัยเสมอ — ชื่อที่แสดงเปลี่ยนทันทีทั้งข้อมูลเก่าและใหม่ |
| **`Code`** | **ห้ามแก้หลังมีข้อมูลใช้รหัสนั้นไปแล้ว** ข้อมูลเก่ายังเก็บรหัสเดิมไว้ พอระบบหารหัสไม่เจอ timeline จะแสดงรหัสดิบแทนชื่อไทย เช่น `EMAIL_RFQ` |
| **`Is_Active = FALSE`** | ซ่อนออกจาก dropdown สำหรับของใหม่ — แต่**กิจกรรมเก่าที่ใช้รหัสนั้นจะแก้ไขไม่ได้** เพราะระบบตรวจค่ากับรายการที่เปิดใช้อยู่เท่านั้น ถ้ายังต้องแก้ของเก่า ให้เปิดกลับชั่วคราว แก้เสร็จแล้วค่อยปิด |

**ห้ามลบแถวทิ้ง** ใช้ `Is_Active = FALSE` แทนเสมอ — การลบแถวทำให้ข้อมูลเก่าอ่านชื่อไม่ออก

### รายการที่มักต้องแก้ตอนเริ่มใช้

| List_Name | ทำไม |
|---|---|
| `COMPANY` | ใส่บริษัทในเครือให้ครบ — จำเป็นต่อการปิดงาน |
| `DEPARTMENT` | ค่าที่ระบบใส่ให้ (`OPS` / `MKT` / `FIN`) เป็นแค่ตัวอย่าง |
| `ACTIVITY_TYPE` | ปรับให้ตรงกับสิ่งที่ Buyer ทำจริง |

## 10. การอัปเดตหลังจากนี้

```bash
clasp push                 # อัปโหลดโค้ด
```

แล้วจาก Apps Script editor:

| เมื่อไหร่ | รันอะไร |
|---|---|
| มีการเพิ่มตาราง/คอลัมน์ใน `Schema.js` | `setup()` |
| ทุกครั้ง | `verifyDeployment()` |

**และต้อง publish เวอร์ชันใหม่ทุกครั้ง** — `Deploy` → `Manage deployments` → กดดินสอที่ deployment เดิม
→ `Version` เลือก `New version` → `Deploy`

ถ้าลืมข้อนี้ ผู้ใช้จะยังเห็นโค้ดเวอร์ชันเก่าอยู่ ทั้งที่ `clasp push` สำเร็จแล้ว

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| เปิดหน้าเว็บแล้วจอว่าง / error ว่าไม่พบไฟล์หน้าเว็บ | `rootDir` หลุดจาก `.clasp.json` หรือชื่อไฟล์ HTML ไม่ตรง — รัน `verifyDeployment()` ดูข้อ 4 |
| ขึ้น "ไม่มีสิทธิ์เข้าใช้งาน" ทั้งที่เป็นคนในองค์กร | อีเมลยังไม่อยู่ในชีต `Users` หรือ `Is_Active` ไม่ใช่ `TRUE` |
| แก้โค้ดแล้วผู้ใช้ยังเห็นของเก่า | ยังไม่ได้ `Manage deployments` → `New version` |
| แก้ dropdown ในชีตแล้วหน้าเว็บยังเป็นค่าเก่า | cache ยังไม่หมดอายุ — ให้ ADMIN เรียก `api_clearCache` หรือรอไม่เกิน 10 นาที |
| เพิ่มประเภทกิจกรรมแล้วไม่ขึ้นในฟอร์ม | `Parent_Code` ไม่ใช่ `M1` หรือ `Is_Active` ไม่ใช่ `TRUE` (ดูหัวข้อ 9) |
| timeline แสดงรหัสอังกฤษแทนชื่อไทย เช่น `EMAIL_RFQ` | มีคนแก้หรือลบ `Code` นั้นในชีต `Config_Lists` — เพิ่มแถวเดิมกลับเข้าไป |
| พิมพ์ชื่อผู้ขายแล้วไม่ขึ้นรายการให้เลือก | ผู้ขายรายนั้นยังไม่อยู่ในทะเบียน — เพิ่มที่เมนู `ผู้ขาย` ก่อน |
| ปิดงานไม่ได้ ขึ้นว่าไม่มีบริษัทในรายการ | ยังไม่เพิ่มบริษัทนั้นในชีต `Config_Lists` (`List_Name = COMPANY`) หรือ `Is_Active` ไม่ใช่ `TRUE` |
| ปิดงานไม่ได้ ขึ้นว่าเลข PR ถูกใช้แล้ว | เลข PR นั้นปิดงานอื่นไปแล้ว — ข้อความจะบอกว่าเป็นงานไหน ให้ตรวจว่าพิมพ์ถูกหรือไม่ |
| ไม่ได้รับอีเมลเตือนรายวัน | ยังไม่ได้รัน `installTriggers()` หรือโควตาอีเมลของบัญชีหมด — รัน `verifyDeployment()` ดูข้อ 11 และ 13 |
| งานที่ปิดไปแล้วกลับมาเป็น "เปิดงาน" เอง | มีคนลบเลข PR ออกจากชีตโดยตรง ระบบจึงเปิดกลับตามกฎ — ดู Change_Log แถวที่ผู้ทำคือ `SYSTEM` |
